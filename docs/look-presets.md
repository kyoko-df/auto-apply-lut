# Look presets

## User workflow

The video and photo inspectors share a look-preset picker. Import media, choose a LUT and strength, then choose **Save current look** and enter a name. An ARW offers an unchecked option to include its current exposure and white balance; the default zero-EV/camera-WB recipe can also be captured. Select a saved preset and explicitly apply it to the current item or the selected items. Applying does not start an export. Use the existing undo action to revert the entire application.

Manage presets from the inspector to rename or delete entries. Deleting a preset does not revert edited clips or delete any LUT/media file. There are no bundled/sample presets. Browser development mode explains that preset operations require the desktop app.

## Contract

- A preset contains an ID, trimmed name, video/photo media type, LUT path and SHA256, 0–100 strength, and optional `SourceInterpretation::Raw`. It does not contain input video conversion, photo RGB profile assignment, source media, output directory, codec, output precision, or photo LUT consent.
- Limit the complete library to 100 entries, names to 80 Unicode characters, IDs to 128 ASCII identifier characters and paths to 4096 Unicode characters. Names are unique case-insensitively within each media type. Reject invalid/nonfinite strengths, broken path/fingerprint pairs, duplicate IDs and invalid RAW parameters on both persistence and frontend mutation paths. Existing settings without presets migrate to an empty library.
- Store presets in `AppConfig.look_presets`, exposed by the existing typed settings IPC. Use the serialized settings-write queue and atomic configuration persistence. Failed changes roll back and are not reported as saved. Invalid preset configuration follows existing byte-preserving config recovery. Preset management does not invalidate completed exports or FFmpeg discovery.
- Before saving or applying, use the existing bounded LUT fingerprint service and LUT validator, and fingerprint again to detect a change during validation. A saved preset requires the same content fingerprint at application. Original LUT files must remain accessible; presets do not package or copy them.
- Video and photo presets cannot cross media modes. A preset that includes RAW development accepts only ARW targets. Validate all selected targets before changing any item; no partial application when one target is incompatible, unread or invalid. Without RAW settings, preserve each target's existing RAW development or RGB profile assignment.
- Applying a photo preset clears the target's previous sRGB LUT consent and fingerprint, including when the LUT path is unchanged. Explicit confirmation must happen again through the existing photo inspector. An older pending confirmation cannot authorize a subsequently applied preset. Video Log confirmation remains with the unchanged batch-wide input-conversion settings.
- Apply through the existing clip transition and one undo snapshot. Retain past outputs while making changed clips ready for re-export. Lock preset operations synchronously, block conflicting edits and export startup while LUT validation is pending, and await the pending operation during native close/OS-quit flushing.
